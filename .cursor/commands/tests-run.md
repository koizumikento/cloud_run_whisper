### 目的

- **テストを素早く反復実行**し、**失敗に基づいて最小限の修正提案→実装→再実行**を繰り返す。
- `uv run python scripts/run_tests.py`（Ruff→Pytest→Coverage）を標準コマンドとする。

### 実行コマンド

- 通常実行: `uv run python scripts/run_tests.py`
- 自動整形込み（Ruff --fix + format）: `uv run python scripts/run_tests.py --fix`
- HTML カバレッジ出力: `uv run python scripts/run_tests.py --html`

### 反復プロセス（TODO）

1) テストを実行して結果を取得する
   - コマンド実行: `uv run python scripts/run_tests.py`
   - 失敗/エラー/警告/カバレッジの差分を要約する（失敗テスト名、スタックトレース先頭、lint 失敗の規則ID）。

2) 失敗に対する最小修正案を作る
   - 影響範囲を最小化すること（過剰変更は避ける）。
   - 優先順位: 型/構文エラー → ロジック差分 → レスポンススキーマ不一致 → テストデータ/モック不整合。
   - 具体的な編集ファイル・該当関数・期待値の差分を提示する。

3) 修正を実装する
   - 指示に従い該当ファイルを編集する。
   - 編集後は linter エラーが無いことを確認（必要なら `--fix` を使用）。

4) テストを再実行する
   - 同じコマンドで再実行し、前回失敗した項目の改善有無を確認。
   - 依然失敗が残る場合は、追加の最小修正案を提示し 2)〜4) を繰り返す。

5) カバレッジを確認する
   - 端末出力のカバレッジサマリを確認（`--cov=app`）。不足がある場合はテストを追加提案。
   - 必要に応じて `--html` を使って HTML レポート生成。

### 成功判定

- すべてのテストがグリーン（exit code 0）。
- Ruff エラーが 0。自動整形後もエラー無し。
- 主要ロジックが期待どおり動作。

### 修正方針メモ

- `WHISPER_SKIP_LOAD=1` がテスト中に設定されるため、モデルはモック差し替えで推論処理を通過可能。
- 例外は握りつぶさず、`HTTPException` を適切に返すこと。
- Pydantic モデルに合わせてレスポンス構造を維持（`info` と `segments[*].words[*].prob`）。

### 最後に

- すべてグリーンになったら変更点の要約と影響範囲を短く記述し、完了とする。
